# 设计决策记录（Decision Log）

> 每条决策写明：背景 → 决定 → 理由 → 证据/代价。新决策追加在末尾，推翻旧决策时注明被替代的编号。
> 恢复工作时先读 `docs/STATUS.md`，再读本文件。

## D1 导演 / 引擎分工：Claude 写语义计划，确定性引擎负责一切“测量”
- **背景**：要让 AI 自主决定“哪里加什么动效”，同时做到逐字逐帧精确、可复现、可修改。
- **决定**：Claude（技能内的 motion director）只产出 `plan.json` —— *加什么、为什么、锚定在哪句话的哪个词*；
  引擎（`engine/semantic_motion`）负责 ASR、时间对齐、版式求解、渲染、QA，全部是确定性代码。
- **理由**：LLM 擅长语义判断（论点、数字、列举、对比、情绪转折），不擅长毫秒级数字和像素几何；
  引擎可单测、可复现（同一计划 + 同一分析 ⇒ 同一帧），改稿只需改计划。
- **代价**：计划质量依赖 Claude 读 `brief.md` 的认真程度；为此 `brief.md` 给出逐句编号、语速、停顿、
  标签（numbers / enumeration / contrast …）、低置信词、镜头与留白方向。

## D2 全本地、零付费栈
- **决定**：faster-whisper large-v3-turbo（词级时间戳）、MediaPipe（selfie multiclass 分割、BlazeFace、Pose lite）、
  OpenCV DB 文字检测（PP-OCRv3 det，用于识别烧录字幕/台标）、skia-python 渲染、ffmpeg 管道编解码。
- **理由**：不需要任何 API key 或账号；用户机器离线也能跑（模型下载后）。Apple Silicon 自动尝试 mlx-whisper 加速。
- **代价**：CPU 上 ASR ≈ 1× 实时、视觉分析 ≈ 1× 实时；1080p 渲染 ≈ 9–12 fps（2 核沙箱实测）。

## D3 自研 Skia 渲染器，而不是 Remotion / 浏览器 / AE 模板
- **理由**：(1) 确定性——每帧是时间的纯函数，可做逐帧哈希比对；(2) 中文排版可控（逐字单元、避头尾、平衡换行、
  高亮标记）；(3) 用户端只需 Python + ffmpeg，无需 Node/Chrome；(4) 直接在源分辨率坐标系作画，再缩放到输出。
- **附加交付**：`--overlay` 导出 ProRes 4444 带 alpha 的图形层，方便剪辑师在 Premiere/FCP/达芬奇里二次调整。

## D4 绝不改变原人物与原声音
- **决定**：无图形、无镜头运动的帧原样透传；音频流不重编码（复制）。
- **验证**（每次 `sm build` 自动做）：解码 PCM 的 md5/相关系数（要求 corr ≥ 0.98、lag ≤ 22 ms，实测为 bit-exact）、
  帧数/时长一致、A/V 偏移 0、图形以外区域 PSNR（< 32 dB 判错，实测 ≥ 45 dB）。
- 颜色：显式传递源矩阵/范围给 swscale（避免 BT.601 默认导致偏色），输出 BT.709 并写元数据；HDR 先 tone-map 到 SDR。

## D5 锚点 = “句号:原话短语”
- **决定**：计划里写 `"3:两千多张"` 这样的锚点（句子编号 + 说出的短语），引擎解析到精确的词/字时间；
  也支持 `w0012`、`12.5s`、`@end`、`+0.3` 偏移。中文按字插值（一个 ASR 词内部的字也能定位）。
- **容错**：相邻句 ±1 容忍、繁简统一（OpenCC）、模糊匹配（≥0.72，产生 ANCHOR_FUZZY 警告）、
  `corrections` 纠正专有名词误识别、**数字口语 ↔ ASR 数字写法**（“百分之四十”/“forty percent” ↔ “40%”，见 D13）。
- **理由**：Claude 只需复制自己读到的原话，不需要处理时间码；改稿时锚点语义不变。

## D6 时间模型：落点对齐“开口那一刻”
- 每个元素的 *落点*（入场动画完成到可读的时刻，`land_frac` × 入场时长）对齐锚点词的声学起点；入场提前开始。
- 列表/流程/对比的每一项在**说到该项时**出现（spoken reveal）；数字在说出时计数；退出优先落在自然停顿上，
  并保证最短阅读时间（按字数/词数计算）。卡片不会空着出场（EMPTY_CARD 规则：卡片入场与第一项同步）。

## D7 词级时间精修：基于基准测试选择 `soft_start + silence_end`（替代早期的 pause_onset）
- **背景**：Whisper 词起点在句首、停顿之后常常提前（实测最大 557 ms），会让图形“抢话”。
- **试过**：`pause_onset`（停顿后首词吸附到最强 onset）——p90 误差变差 40–50 ms，**弃用**；
  硬 VAD 吸附 `silence_start` —— 不如原始值。
- **决定**：只修正“落在静音里的词起点”：向后找到第一个响度超过 `noise_floor + 0.2·(speech − noise)` 的 hop，减 20 ms；
  词尾落在静音里则回拉到最后一个有声 hop。
- **证据**（合成基准，见 TEST_REPORT §3）：英文 p90 76.2 → 67.5 ms，最大误差 557.5 → 85 ms，±2 帧内 91.1% → 96.4%；
  中文 ±1 帧内 64.2% → 69.8%，其余持平。

## D8 版式求解：代价场 + 硬障碍，脸永远是硬障碍
- 对元素整个生命周期汇总视觉分析：脸/头（带上方发型余量）、平台安全区 = **硬障碍**；身体、手势热区、运动、
  烧录文字、杂乱度、亮度 = 代价。对每个尺寸候选、每个缩放档、每个网格位置穷举求最小代价。
- 竖屏（9:16）允许文字放在下巴以下的胸前（平台惯例），`chin_margin = 0.06`；横屏优先开放侧（open side）。
- 跨跳切（jump cut 到特写）时整个生命周期无安全位置 → `CLIPPED_TO_SHOT`：只保留有空间的连续镜头段，入场最多推迟 0.8 s。
- 背景过亮/杂乱时自动加毛玻璃底板（AUTO_BACKING）。

## D9 默认“智能均衡”（balanced）
- 同一时间只有一个主图形；4–9 个/分钟；≥35% 时长保持干净画面；数字与列举优先，寒暄/口头禅跳过。
- 另有 `minimal` / `bold` 风格与 `density` 参数，供改稿（“太多了”→ minimal）。

## D10 QA 两级 + 自动修复 + “看真实成片”
- 渲染前（timeline 级）：锚点、落点偏差、阅读时间、脸/头/字幕遮挡、碰撞、安全区、对比度、密度、干净比例。
- 渲染后（文件级）：帧数、时长、音频一致性、A/V、透传 PSNR、图形是否真的出现在框内（GRAPHIC_MISSING）。
- 可确定修复的问题自动修（换位、缩小、加底板、卡片对齐首项），并在报告中列出改了什么。
- 联系表（contact sheet）**从渲染后的成片文件抽帧**，在每个元素“完全展开”的时刻取帧，Claude 必须看过才能交付。

## D11 项目目录即记忆
- `<video>.smproj/`：分析缓存按输入哈希判定新鲜度；每次 build 快照计划 `plans/plan.NNN.json`；`history.jsonl` 追加日志。
- 支持 `sm status / diff / undo`，任何中断都能从项目文件恢复，改稿可撤销。

## D12 启发式 auto-plan 只是基线
- `sm auto-plan`（无 LLM）：数字→stat、列举→list、强重音关键词→keyword、长段落→镜头推进。
- 关键词要求 ASR 词置信度 ≥ 0.8（在 OpenClaw 快语速素材上曾把误识别词“卖客/滑拉”做成花字）。
  代价：在困难素材上可能只剩镜头运动。**正式流程以 Claude 导演计划为准**，auto-plan 仅作起点/冒烟测试。

## D13 口语数字锚点回退
- **背景**：基准测试发现“百分之四十 / 两万 / forty percent / twenty thousand”找不到，因为 Whisper 写成 “40% / 2万 / 20,000”。
- **决定**：锚点搜索时为短语生成数字写法变体（中文数词、英文数词 → 阿拉伯数字、万/千写法、k/thousand），
  先所有候选精确匹配，再模糊匹配。
- **证据**：合成基准 9/9 探针短语全部解析，误差 −45 … +145 ms（TEST_REPORT §3）。

## D14 custom 元素：声明式图层 + 关键帧，而非执行任意代码
- 一次性的视觉想法（时间轴、倍数、地图钉、简易图示）用 `custom`：rect / text / line / circle / counter 等图层，
  关键帧可以锚定到说出的词（`"6:first started"`）。
- **理由**：安全（不执行生成代码）、确定性、可被同一套版式求解和 QA 覆盖。

## D15 QA 框不再二次缩放（缺陷修复）
- **发现**：新增的集成测试 `test_rendered_footprint_matches_qa_box` 把 QA 使用的框与实际渲染出的 alpha 包围盒比对，
  发现 `element_box_at` 把已经包含缩放的框又乘了一次 `scale`：缩放 < 1 时低估（漏报风险），`size: l`（1.16）时高估
  （竖屏 flow 误报 OUTSIDE_SAFE）。
- **决定**：编译器存储的 `box` 就是最终占位；QA 直接使用。实测渲染范围 = box + 柔和阴影（约 1.5u）。

## D16 已有烧录字幕 → 默认不加字幕，并避让字幕区
- 视觉分析检测画面内文字（DB 文本检测），brief 中给出警告；版式把文字区域计入代价（TEXT_OCCLUDED 为错误）。

## D17 镜头推进不得裁掉烧录字幕/姓名条
- **发现**：中文横屏结尾的 punch-in（1.10×）在联系表中把底部烧录字幕裁掉了一半。
- **决定**：编译镜头运动时，把“持续存在的画面文字”（overlay_text，及其所在行内的逐镜头检测）与人脸一起作为必须保留在画面内的区域，
  求解可行的缩放中心；不可行则逐步减小缩放；仍不可行（≥1.02 时）则跳过并给出 `CAMERA_CROPS_TEXT`。
  背景中的普通文字（海报、书脊）不受保护，按普通物体处理。
- **结果**：zh 16:9 结尾推镜缩放中心从 y 0.36 → 0.76（字幕完整保留）；en 16:9 推镜中心移到左下角以保留烧录姓名条；
  zh 9:16 派生竖屏里字幕横贯全宽，推镜被判定不可行 → 导演在计划中禁用该镜头（`enabled: false` 并写明原因）。

## D18 改稿局部性：一个元素的改动不得牵连其他元素
- **发现**：英文样片改稿“把 +18 放左边”后，15 s 之后的流程卡也跟着跑到左边——版式的“同侧一致性”沿用了上一个元素的侧别。
- **决定**：侧别一致性只在相邻图形间隔 < 4 s、且上一个元素是自动摆放（未被用户指定 region）时才继承。
- **结果**：改稿后只有被要求的元素移动（验证见 TEST_REPORT §5）。

## D19 `sm diff` 输出字段级差异
- 改稿说明需要“改了什么”一目了然：`sm diff` 现在自动选择与当前计划不同的最近快照，逐字段列出
  `~ versions.placement: (none) -> {"region": "left"}`、`- spirit (keyword)`、`~ accent: "auto" -> "sky"`。

## D20 导演的克制：在已经包装过的素材上少加
- OpenClaw 片段本身就有大量 B-roll、录屏和自带动效。预览后导演禁用了两个与原片图形冲突/重复的元素，
  只保留 3 个（以说话人镜头为主）。`enabled: false` 保留在计划里，改稿时一句话即可恢复。
